# Provide public DNS and HTTPS

Public management routing requires one explicit origin policy. `publicIngress.mode`
is either `tunnel` (the default generated by setup) or `direct`. There is no
world-open origin mode.

The local controller remains available only through admin's restricted Unix
sockets. The management and authentication applications are not implemented, so
a healthy platform route proves ingress only; see
[MANAGEMENT_APP_SPEC.md](MANAGEMENT_APP_SPEC.md).

## Ingress modes

### Authenticated tunnel

```json
"publicIngress": {
  "mode": "tunnel",
  "providerCidrs": []
}
```

Traefik binds its HTTP entry point to `127.0.0.1:80`. Neutron and the NixOS
firewall expose no public HTTP or HTTPS origin port. The tunnel agent must run on
the ingress host and forward to `http://127.0.0.1:80`; an external reverse proxy
cannot connect directly to the ingress address in this mode.

Cloudflare Tunnel is the reference agent. Supply its token as a direct,
current-user-owned mode-`0600` file:

```bash
umask 077
install -m 0600 /path/from-secret-store /private/cloudflare-tunnel-token
uv run openstack-platform setup \
  --env-file /private/setup.env \
  --cloudflare-token-file /private/cloudflare-tunnel-token \
  --apply
```

The token is embedded only in the protected temporary config-drive payload. Do
not put it in `platform.json`, logs, or command arguments. Without a token,
setup leaves the tunnel unconfigured and reports public ingress as pending; it
does not open the origin.

### CIDR-restricted direct origin

Use direct mode only when the HTTPS provider publishes stable IPv4 origin
ranges:

```json
"publicIngress": {
  "mode": "direct",
  "providerCidrs": ["203.0.113.0/24", "198.51.100.7/32"]
}
```

Each entry must be a canonical IPv4 network with no host bits. The list must be
nonempty and cannot contain `0.0.0.0/0`, IPv6, or duplicates. The same exact
list controls Neutron rules, the NixOS firewall, and Traefik's trusted forwarded
headers. Only provider sources may reach origin port 80; origin port 443 is not
opened. Public clients still use provider-terminated HTTPS.

Setup input uses:

```dotenv
PLATFORM_INGRESS_MODE='direct'
PLATFORM_PROVIDER_CIDRS='203.0.113.0/24,198.51.100.7/32'
```

A Cloudflare Tunnel token and `direct` mode are mutually exclusive. Missing or
malformed direct CIDRs fail during the non-mutating setup check and before an
OpenStack connection or workspace mutation.

## Provider contract

For both modes, the public provider must:

1. resolve the configured platform and project hostnames;
2. present a browser-trusted HTTPS certificate;
3. preserve the original HTTP `Host` header;
4. forward to the mode-specific HTTP origin described above; and
5. allow `/healthz`.

Future project routes use `<slug>.<domain>`. The provider may use wildcard DNS
and certificates or provision each hostname separately. Traefik routes by the
preserved `Host`; replacing it with an origin address selects no intended route.

```text
browser -- HTTPS --> public provider -- mode-specific HTTP --> Traefik
```

## Migrate an existing origin

Before reconciling an existing deployment, add `publicIngress` to the private
inventory and run the configuration and Nix evaluation checks in
[CONFIGURATION.md](CONFIGURATION.md). Do not use `0.0.0.0/0` as a temporary
migration value.

Reconcile the foundation security groups before replacing the ingress image.
For direct-to-direct changes, reconciliation adds the new exact rules before
removing stale HTTP/HTTPS rules. For tunnel mode, it removes all public origin
rules. Then build, test, select, and replace the ingress image so the host
firewall and Traefik binding match the inventory. Verify the public path below.
Do not roll back by restoring a world-open rule; select the previous tested mode
only if it also has an admissible policy.

## Verify the public path

```bash
PLATFORM_HOSTNAME=apps.example.edu
test "$(curl --fail --show-error --silent \
  "https://$PLATFORM_HOSTNAME/healthz")" = OK
```

This verifies DNS, certificate validation, provider forwarding, original-host
routing, and Traefik. A direct request to the ingress address is not a supported
health check. In tunnel mode it must be unreachable; in direct mode a source
outside `providerCidrs` must be rejected even when it supplies the management
`Host` header.

| Symptom | Check | Correction |
| --- | --- | --- |
| Origin connection is refused | Compare the selected mode and provider source with `publicIngress` | Run an on-host tunnel agent, or add only the provider's exact canonical CIDRs in direct mode |
| Traefik returns no route | Compare the forwarded `Host` with the public hostname | Preserve the original `Host` |
| Setup rejects ingress configuration | Check mode, canonical CIDR network addresses, duplicates, and `/0` | Correct the environment file; setup has not mutated the workspace or OpenStack |
| Public health fails but origin is intentionally closed | Inspect the tunnel service and provider route | Restore the authenticated tunnel; do not open a public origin |

See [CONFIGURATION.md](CONFIGURATION.md) for the inventory schema and
[CONTROL_PLANE_CONTRACT.md](CONTROL_PLANE_CONTRACT.md) for the operator/controller
boundary.
